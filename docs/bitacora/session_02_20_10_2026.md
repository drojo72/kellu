# Session 02 — October 20, 2026

## 1. Context & Objective
* **Technology:** Ruby, Thor, `secret-tool` (XDG Secret Service backend executed via `Open3`).
* **Objective:** Consolidate an interactive CLI tool for managing local Linux credentials (creation, synchronized listing by categories, and accurate deletion via keyring attributes).

---

## 2. Diagnosis of Previous Parsing Failure
* **The Parser Problem:** Initial filters relied on finding a flat attribute line `attribute.service = ...` in the output of `secret-tool search --all`. However, `secret-tool` structured records using numerical index blocks (`[/N]`) and exposed metadata primarily through `label = Kellu: ...`.
* **Consequence:** 
  * Strict attribute-based filters discarded entire blocks, resulting in empty outputs.
  * Previous attempts to guess the service name by truncating words broke compound names and caused mismatches with `secret-tool clear`.

---

## 3. Final Solution Implemented and Validated
* **Block Parser & Extraction by Label (`lib/kellu/security/keyring.rb`):**
  * Implemented a linear block parser that detects record starts using index patterns (`[/N]`).
  * Extracted the true service name cleanly by capturing the last structured word from the label string (`Kellu: [description] [service_name]`).
* **Storage Standardization (`set_secret`):**
  * Aligned credential creation so `--label` and attributes synchronize symmetrically with reading and clearing procedures in the system keyring.
* **Current Result:** 
  * Completely stable CRUD cycle. The CLI saves, deletes without errors, and updates listings in real time smoothly.
